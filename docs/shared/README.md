# Shared Reports — التقارير المشتركة

استخدم هذا المجلد عندما يشترك أكثر من شخص أو أكثر من Track في هدف أو قرار أو تسليم واحد. ملفات `STATUS.md` تعرض الحالة المختصرة وتربط بالتقرير المشترك؛ التقرير المشترك هو المصدر الوحيد للتفاصيل المشتركة.

## التسمية

`YYYY-MM-DD-short-topic.md`

مثال: `2026-11-19-backend-flutter-auth-contract.md`.

## طريقة الاستخدام

1. انسخ [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md) باسم جديد.
2. اكتب أسماء الأشخاص المؤكدة فقط، واستخدم `TBD` لغير المعروف.
3. حدد كل Tracks/Departments المشاركة.
4. اربط الأدلة والـSHA والتواريخ لكل بند مكتمل.
5. أضف رابط التقرير إلى ملفات `STATUS.md` المعنية.
6. افصل حالة التنفيذ عن حالة التوثيق/التحقق؛ قد يكون التنفيذ `Completed` بينما التحقق `Unknown` أو `Needs re-verification`.
7. سجل كل dependency أو handoff مع الـTrack المسؤول، حالته، المطلوب لتأكيده، والرابط إلى هذا التقرير.
8. عند انتهاء العمل، غيّر حالة التنفيذ إلى `Completed` وحالة التحقق إلى `Verified` فقط إذا وُجد الدليل؛ لا تحذف blockers أو decisions التاريخية المهمة.

## منع التقارير القديمة من التضليل

- `Last updated` يوضح آخر تعديل تحريري، و`Last verified date` يوضح آخر مرة فُحصت فيها الأدلة؛ لا تخلط بينهما.
- `Unknown` يعني غير متحقق، ولا يثبت أن العمل غير موجود أو لم يبدأ.
- بعد 7 أيام من `Last verified date` أثناء العمل النشط، ضع `Needs re-verification` إلى أن تُراجع الحالة.
- لا تنسخ نفس قائمة المهام بين عدة ملفات. استخدم رابطاً للمصدر الرئيسي.
- إذا تعارض تقرير قديم مع دليل أحدث، اربط بالدليل الأحدث وسجل القرار بدلاً من تعديل التاريخ بصمت.
