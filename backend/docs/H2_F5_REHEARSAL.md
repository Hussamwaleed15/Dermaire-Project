# Current H1/H2 isolated schema rehearsal

Historical app.tools.rehearse_index_adoption assumed a pre-revision schema/head, seeded current ORM against an old baseline and compared entire-row hashes across new columns. Those assumptions are no longer valid. Its entry point now fails immediately BEFORE target/config/database access, explaining that it is retired for current H1/H2. The historical implementation/evidence remains available for review, not certified as a current executable or current production evidence. No production adoption SQL/Azure config was edited or executed.

Replacement app.tools.rehearse_current_schema accepts ENVIRONMENT=test only. PG is restricted to driver postgresql+psycopg, gate user, literal 127.0.0.1:55441, random dermaire_gate_<32 hex> database name; SQLite requires a dedicated dermaire_rehearsal_* file. URL query parameters/other drivers are rejected. The database must have NO existing tables: no overwrite, drop, adoption or migration of an existing application DB. Tests prove wrong host/port/user/name, production environment and occupied SQLite/PG targets are refused. Do not run it as a regular application startup test against an existing local DB.

It creates frozen 20261008_01 schema, seeds 8 synthetic rows in users/products/routine/experiments/adherence/check-in/grants, snapshots ALL original columns across all business tables, upgrades through product/routine/experiment/adherence migrations to 20261014_04, runs Alembic check, and compares every original row value/count. New revision defaults verified for all three configuration resources. Legacy active grant with old export bool does not gain EXPORT; owner-bound persisted report/manual attempt still reconciles and foreign actor remains unknown. Actual source contracts, not prior report assumptions, supply the fixture.

Separate focused migration tests additionally prove seeded product/routine/experiment/adherence preservation, plain downgrade/re-upgrade and refusal to discard protected revisions or durable receipts on BOTH SQLite and PG. A multi-revision SQLite downgrade can apply earlier unprotected steps before a later guard fails; SQLite does not promise atomic multi-DDL rollback. After any failed downgrade inspect the actual Alembic/schema state; do not assume the whole chain reversed. No real DB downgrade/migration was attempted.

Evidence artifacts H2_SCHEMA_REHEARSAL_SQLITE.json and H2_SCHEMA_REHEARSAL_POSTGRESQL.json contain only synthetic row counts/digest, DB version, driver, head and gate outcomes. PostgreSQL is 18.6 on Windows; SQLite version is recorded from its real connection. This is current schema/data compatibility rehearsal, not historical production catalog/index adoption, live deployment, managed role/ACL/collation equivalence, performance, RPO/RTO or DR certification.

Run via the isolated backend test runner with a workspace --basetemp and DERMAIRE_LOCAL_PG_GATE=55441. The PG fixture creates/drops its own DB. DERMAIRE_REHEARSAL_EVIDENCE_DIR optionally saves the synthetic JSON reports. CLI requires DERMAIRE_REHEARSAL_URL and DERMAIRE_REHEARSAL_OUTPUT and refuses an occupied target. It never accepts application DATABASE_URL as a fallback target. No cloud credentials/providers or live accounts were used.
