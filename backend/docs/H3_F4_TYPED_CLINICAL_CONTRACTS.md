# H3-F4: explicit clinical response DTOs

Registered response models now cover:
- GET /api/v1/doctor/review-status -> ReviewStatusOut (patient owner).
- GET /api/v1/doctor/patients/{patient_id}/reviews -> ReviewStatusOut (doctor/current VIEW grant).
- POST same reviews path ->201 ReviewActionOut (doctor/current VIEW grant; existing expected_sequence).
- GET /api/v1/doctor/patients/{patient_id} -> DoctorPatientDetailOut.
- GET /api/v1/doctor/patients/{patient_id}/timeline -> DoctorTimelineOut, existing offset/limit.
- GET /api/v1/doctor/access -> list[AccessGrantOut]; DELETE /api/v1/doctor/access/{access_id} -> AccessGrantOut.
- Existing POST/GET clinical notes retain ClinicalNoteOut/list[ClinicalNoteOut], now with schema_version clinical-note-1.0, fixed priority/provenance enums and UTC dates.

ReviewActionOut fields: schema_version=clinical-review-1.0; id, sequence, patient_id, doctor_id, access_id, state, recommendation|null, rationale|null, patient_visible, created_at, provenance=clinician_authored, safety_at_review:SafetyEvaluation, diverges_from_current_safety, lower_than_current_safety, urgent_safety_preserved; F3 is_current:boolean|null, resource_revision=sequence, safety_at_review_kind=historical_saved, current_safety_evaluation_id|null, clinical_clearance=false. Sequence positive; revision must equal sequence. No scheduled_at/due_at/appointment/verification badge. is_current null only for an unclassified internal projection; status/history always supply true/false.

ReviewStatusOut keeps schema_version doctor-loop-2.0 and fields patient_id/state/latest_sequence/changed_at|null/changed_by|null/safety/current_decision|null/history/notes/access|null. F3 fields as_of/consistency/current_decision_visibility are explicit. State is not_requested|pending|in_review|reviewed|follow_up_needed. Current must match patient/latest sequence and be current. History descending unique sequence; owner/current flags validated. Unavailable current visibility cannot carry current content. Notes/grants in status must share patient owner. Doctor view access:null remains existing behavior, not denied access; detail has the current authorized grant separately. Patient access list can be empty. Private newest decision never triggers visible older fallback.

ClinicalNoteOut keeps id/doctor_id/patient_id/content/priority/follow_up|null/created_at/updated_at/category|null/patient_visible/timeline_item_id|null/review_action_id|null/provenance; new schema_version clinical-note-1.0. Priority routine|review|urgent, provenance clinician_authored. Timestamps normalize stored naive UTC to offset-aware UTC and preserve real instants for already aware values. Notes remain immutable and free-text follow_up remains literal. None/absent follow_up is no recorded text, not a scheduled or completed appointment. Optional evidence links identify actual same-patient records validated by existing write handlers.

AccessGrantOut publishes existing actor, owner, status, timestamps, scope and consent-source fields. Status pending|active|revoked|expired, consent_source explicit_patient_intent|legacy_view_only, consent_version2|null, scopes/effective_scopes VIEW|EXPORT. Nullable doctor/actor/times preserve unknown legacy/pending state. No token is in this response. Existing QR/claim compatibility is retained; no new export capability.

DoctorPatientDetailOut: patient_id,full_name,access:AccessGrantOut,review:ReviewStatusOut. DoctorTimelineOut: schema_version doctor-timeline-2.0,built_at,items,unknowns,derived_source_availability,safety,limitations,total,offset,limit,next_offset|null. Items explicitly type id/source/source_id/field/category/recorded_at|null/provenance/data. Polymorphic source-specific data/provenance and source availability stay dictionaries intentionally, not invented fixed clinical fields. Ordering remains timestamp+stable ID ascending (unknown first), reviews in status sequence descending; offset pagination is not a snapshot cursor.

SafetyEvaluation is typed in current and saved review responses. Old well-formed snapshots with no provenance return provenance:null (unknown historical provenance), never a new evaluation. Invalid enum/required data fails response validation and cannot become successful clearance. Current engine authority unchanged. saved snapshot values are not written/rewritten by response validation. Safety evaluated_at normalizes UTC.

Requests unchanged: note content10..1500, optional category<=50/follow_up<=100/links, patient_visible defaultfalse, priority defaultroutine. Review state required, expected_sequence integer>=0 required, recommendation optional one of track|low_risk_self_care|doctor_review|urgent, rationale10..1500 required when recommendation supplied, visibility defaultfalse. Strict validation rejects unsupported fields/invalid states422. Existing patient row/grant locks, unique(patient_id,sequence) and409 stale expected_sequence are preserved.

Security/compatibility review: response enums reflect actual DB constraints, actor IDs remain actual records, no license badge, current grant rechecked by existing authorization, owner/visibility filtering unchanged, all legacy fields retained.
