# DERMAIRE — التقرير العربي لدفعة الإكمال الخلفية بعد التوسعة

التاريخ: 2026-10-16 — Africa/Cairo.

نُفذت دفعة Backend كبيرة في نسخة Git معزولة من المستودع القانوني، بعد التحقق
مستقلًا أن نقطة البداية البعيدة هي
`275e753b3d07cbe86f0aed08d558802355ce2c6d`. لم تُعدّل ملفات Flutter أو Tester أو
الملفات الأصلية للمنصات، ولم تُستخدم أجهزة أو محاكيات أو Azure حي أو قواعد بيانات
حية أو اتصالات مزودين مدفوعة. البرنامج الكامل ما زال PARTIAL؛ هذا التقرير لا يدعي
اعتمادًا سريريًا أو جاهزية إطلاق إنتاجي.

## ما اكتمل في المصدر

1. إيصالات SQL أصلية للملاحظات والمراجعات السريرية، وإصدار/claim/سحب منح الطبيب
   الفردية والجماعية، مرتبطة بالممثل والمريض والطبيب والمنحة والحمولة والمفتاح.
   تدعم استعادة الرد المفقود وقراءة النتيجة الأصلية، وتحافظ على CAS والمراجعة
   الحالية الخاصة. لا تعيد دعوة QR مستهلكة أو مسحوبة أو منتهية.
2. قراءة إيصال إكمال سياسة السلامة بالإصدار الصحيح ومراجعة الملف v1 من التدقيق
   الذري الفعلي. غياب التدقيق في بيانات قديمة يرجع unknown بدل اختلاق النجاح.
3. سجل append-only مستقبلي لإعدادات الروتين من writers الفعلية: إنشاء/تعديل/إيقاف،
   أرشفة المنتج، وتدخل التجربة، مع نسخة إعداد كاملة ودليل المنتج ومصدر الكاتب.
   القراءة خاصة بالحساب وبمؤشر موقع منتهي الصلاحية وتصرح أن cutoff ليس MVCC.
4. سياسة تقويم IANA مستقبلية بإصدارات CAS ووقت سريان من الخادم. بقيت تواريخ
   الالتزام القديمة وفريد `(entry,date,slot)` على UTC؛ لا إعادة تفسير تاريخية.
5. تذكيرات روتين AM/PM/BOTH بوقت محلي ومنطقة IANA وfold صريح وسياسة gap=skip،
   وتوليد محدود وهوية occurrence ثابتة ومنع ازدواج PostgreSQL. التعديل/الإيقاف/
   الأرشفة/سحب الموافقة/logout/حذف الحساب تلغي وتسيّج الآثار المناسبة.
6. عامل تنبيهات منفصل لا يقبل إلا قاعدة SQLite مصطنعة صريحة أو بوابة PostgreSQL
   المحلية المخصصة. يسجل كل lease ومحاولات retry/unknown/provider_accepted، ولا
   يحول قبول المزود إلى delivered. حمولة push العامة لا تحتوي PHI.
7. انتقال read/unread وصندوق تاريخ خصوصي للحالة الحالية/الملغاة ومحاولات العامل.
   تاريخ ما قبل migration13 غير مختلق، وحذف الحساب يمحو أدلة المحاولة.
8. دورة طلبات وكيل موجهة للطبيب: موافقة مريض مستقلة، inbox طبيب، قبول/رفض/review
   مع CAS، TTL، سحب ومحو ذاكرة، وإشعارات محلية بعد commit الفعلي فقط. عولجت سباقات
   حذف الطبيب وسحب الجلسة بصفوف مقفلة وترتيب ثابت وNOWAIT آمن.
9. أداة غير سريرية حقيقية وحيدة `mark_notification_read` عبر preview ثم confirmation
   صريح وفحص الملكية والمصدر والحالة unread ومعاملة واحدة. المقترحات السريرية لا
   تنفذ علاجًا أو تعدل خطة.
10. عقد مزود Agent صارم ومغلق افتراضيًا. النص غير الموثوق لا يختار أداة. إن لم يوجد
    adapter مهيأ حقيقيًا فالنتيجة unavailable ولا تُختلق إجابة نموذج.
11. طابور تقييم مقارنة صور مرتبط بخطة طبيب وصور baseline/follow-up الخاصة وموافقة
    معالجة حديثة: queue/lease/retry/cancel/fencing ومراجعة بشرية صريحة مرتبطة
    بالـjob وإصدار النموذج وSHA للأثر. لم يوجد model artifact موثق في المستودع؛
    الاختبارات الاصطناعية تقبل فقط flags جودة صورة غير سريرية بلا تشخيص أو نسبة تحسن.
12. حذف الحساب الثنائي ومسار الاستعادة الموقع يغطيان الإيصالات الجديدة، سجل
    الروتين، التقويم، الطلبات الموجهة، التنبيهات ومحاولاتها، مع اختبارات عزل المالك.

## الترحيل والعقود

الترتيب الجديد بعد `20261015_09` هو:

`20261015_10` إيصالات سريرية ومنح → `20261015_11` تاريخ الروتين والتقويم →
`20261015_13` التذكيرات ومحاولات التنبيه. لا يوجد migration12. readiness يتطلب13.
الترحيلات تضيف جداول/أعمدة فقط، ولا تحول بيانات UTC القديمة ولا تولد تاريخًا خلفيًا.
الـdowngrade يرفض فقد البيانات الجديدة عندما تكون الجداول ممتلئة.

تسليم Amr الكامل في `EXPANDED_FLUTTER_HANDOFF.md`: المسارات الحقيقية، الأمثلة،
الأخطاء 401/403/404/409/410/412/422/428/503، حفظ المفتاح والـCAS عند الشك، دلالات
UTC/local/DST، وإظهار unavailable/unknown/provider_accepted دون ادعاء delivered.

## التحقق الحقيقي

النتيجة النهائية: **1137 اختبارًا ناجحًا، منها 90 حالة PostgreSQL فعلية، صفر فشل،
صفر خطأ، وصفر تخطٍ**، خلال 346.31 ثانية. شملت الجولة SQLite القديم، PostgreSQL
منع الازدواج والأقفال والسباقات والتراجع، seeded migration من المخطط القديم حتى 13،
`alembic check` بلا drift، حذف/استعادة الخصوصية، وسياج العمال القديمة.

نجح `compileall`، وتوليد OpenAPI بـ 114 مسارًا و117 schema، و`git diff --check`.
ظهر 217 تحذير deprecation من الاعتماديات، بلا فشل. أول جولة كاملة بعد الدمج كشفت
مشكلتي توافق حقيقيتين (حذف مصدر تاريخ الروتين وتكرار audit للسحب القديم): لم تُخفيا؛
أُصلحتا ثم نجحت جولة 84 مركزة والجولة الكاملة النهائية. تعذر setup واحد سابقًا بسبب
صلاحيات مجلد pytest المؤقت العام في Windows؛ أُعيد داخل مجلد المحادثة دون تغيير
صلاحيات الجهاز.

ملف JUnit والدليل محفوظان محليًا تحت `work/evidence-final` خارج Git. لم تُمس أي
عناقيد PostgreSQL محفوظة مسبقًا؛ استُخدم عنقود جديد خاص بهذه المحادثة على loopback.

## ما بقي بدقة

- BLOCKED: مزود push حي، أسراره، hosted scheduler/worker، تحقق idempotency والمهل
  والخصوصية، أجهزة فعلية وإثبات delivered. القبول عند المزود ليس وصولًا للجهاز.
- BLOCKED: model artifact مقارنة موثق، تحميل صور آمن، تدريب/تحقق نموذجي وسريري،
  governance للنتائج ودليل دقة. لا توجد تشخيصات أو نسب تحسن مصطنعة.
- BLOCKED/OPEN: adapter نموذج Agent حقيقي مقيد ومراجع، وموافقات provider/clinical.
- OPEN: registry دائم شامل لحالات rejected/in-flight لكل النطاقات؛ الإيصالات الجديدة
  تثبت committed فقط وunknown لا يثبت الرفض. مفاتيح M1 ما زالت اختيارية للتوافق.
- OPEN: انتقالات onboarding مستقبلية بإصدارات جديدة، وnamespace محلي جديد للالتزام
  إن تقرر ترحيله؛ الحالي يبقى UTC بأمان.
- OPEN: أدوات غير سريرية إضافية بعد allowlist وعقود مستقلة، وصفحات doctor request
  بعد أول 100 عنصر، وتاريخ/لقطات MVCC تاريخية شاملة لكل النطاقات.
- OPEN: Flutter integration واختبارات الأجهزة، وأي تشغيل staging/production/DR/TLS/
  performance أو اعتماد سريري/قانوني.
