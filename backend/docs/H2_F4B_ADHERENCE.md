# Incremental durable adherence receipts (F4 remains PARTIAL across domains)

POST /api/v1/routine/adherence now accepts optional Idempotency-Key, 16-128 ASCII letters/digits/_/-. Duplicate or malformed header is 422. No-key callers keep existing uniqueness/validation semantics and receive receipt:null. This is one implemented domain; products/routine configuration/experiment/clinical/grant attempts have NOT gained generalized receipts.

GET /api/v1/routine/adherence/attempts/{key} is registered under the existing routine router and requires the current account. Returns schema_version=1, operation=routine_adherence, opaque attempt_id, owner_id=actor_id, status committed/unknown/expired, and nullable result/resource_id/configuration_revision/server commit/expiry times. A typed committed result is the original AdherenceOut, with a typed receipt. Result includes original snapshot/note already stored for this owner; hash/raw key are never returned or audited. Response validators reject inconsistent actor/resource/receipt scope. Foreign account's same key is unknown, not another user's result; foreign routine submission is 404. Missing/expired authentication is 401.

Stable UUID5 primary key binds owner+actor+operation/version+key. SHA256 binds validated entry/date/slot/status/exact nullable note. The existing PK and UNIQUE(entry,date,slot) prevent blind duplication. Same key+payload returns original 201/result without rewriting the snapshot or adding audit, including after current entry was stopped. Different payload is 409. Another key for an occupied slot is 409, and lookup for that key remains unknown: slot uniqueness alone is not a receipt. Unknown never proves rollback/failure and never authorizes a new key.

Business event, attempt metadata and allowlisted audit share one DB transaction. The receipt lives in a nullable JSON column on the immutable adherence event, added by 20261014_04 (parent 20261014_03); not a superficial cross-domain table. On unique insert collision, losing transaction rolls back then reauthorizes owner-bound winner and checks exact hash; database uncertainty returns 503. Corrupt attempt metadata returns failed lookup (503), never fabricated committed/unknown. No persisted lease/reservation/rejection registry, so in_flight/rejected are not asserted. No external provider effects or exactly-once claim.

Replay lasts 30 days from immutable server created_at in UTC; at/after expiry POST is 410 and GET is expired with original resource/timestamps, result:null. Original owned adherence history remains available via GET /routine/adherence (filter routine_entry_id and paginate as usual). Metadata/tombstone remain for record lifetime, not deleted automatically at day 30. Account deletion and journal replay already remove owned RoutineAdherence, so metadata is erased with the event; deleted authentication cannot look up/replay. No extra retention of raw attempt keys or clinical data is introduced. Downgrade is blocked while any attempt metadata exists.

configuration_revision proves the snapshot used for that report, not current routine configuration or attempt-specific configuration update success. Adherence does not edit routine configuration and does not require If-Match; it keeps the existing owner lock, latest configuration-day validation and UNIQUE contract. A routine configuration revision does not promise an unchanged evidence/coverage projection. Amr must persist random key+normalized payload+account before send, retain it on timeout/restart, consult attempts, retry only same key/payload when unknown, and reconcile original history when expired. Do not interpret 409, 5xx, unknown or auth failure as committed.
